# 🎭 多角色舞台系统

> 舞台 = 一群角色共享同一个叙事场景。你创建多个角色卡，它们会在同一段命运中互相回应、交锋、并肩。

## 🏗 舞台目录约定

舞台的组织方式与单角色契约完全一致，只是把多个角色卡放进**一个子目录**：

- **舞台 = 契约根目录下的「一层子目录」**，文件夹名 = 舞台名（如 `Camlann/`）
- 舞台内含 **N 份平级 `.meph` 角色卡**（如 `Arthur.meph` / `Mordred.meph`）
- 每个角色各自的运行时存档为 `舞台/角色名.child.meph`（引擎自动生成，无需手写）
- **不做深层嵌套**：舞台目录内只放平级角色卡，不支持子目录
  （避免与「单角色子版基于 `.` 分段推导」混淆）

```text
契约目录/
├── faust.meph          ← 单角色契约（不受影响）
├── dantes.meph
└── Camlann/            ← 舞台 = 一层子目录
    ├── Arthur.meph
    ├── Mordred.meph
    ├── Arthur.child.meph   ← 自动生成的存档（不用管）
    └── Mordred.child.meph
```

## 🚀 如何创建舞台

1. 在契约目录下新建一个文件夹（如 `我的舞台/`）
2. 将每个角色写成一个 `.meph` 契约文件，放入该文件夹
3. 刷新首页 → 「多角色舞台」区自动出现该舞台卡片

> 💡 也可以使用首页「导入」功能解压别人分享的舞台 ZIP（舞台目录会原样还原）。

## 📜 角色卡格式

舞台内的角色卡**复用完整契约语法**（区块、状态、规则、骰子、记忆等见 [契约语法参考](contract-syntax.md)），额外约定：

- **公共世界观**：整个舞台的【世界观】取**第一个角色卡**（按文件名字典序排在最前的那份）
- 每个角色的【锚点】【状态】【记忆】【规则】**独立运行**，互不混淆：
  - 亚瑟王触发状态变更，不会影响莫德雷德的状态
  - 每个角色只看到自己的记忆，看不到别人的过往

## ⚙️ 叙事机制

多角色舞台的每一轮生成：

1. **每位角色各自运行规则引擎**（状态变更、记忆注入、骰子判定独立隔离）
2. **单次 LLM 调用**：所有角色共享同一段命运指引
3. **输出为「全景叙事流」**：一段流畅的第三人称小说，自然提及有戏份的角色
   - 有戏份的角色在同一段文字中互动（对话 / 动作 / 交锋）
   - 未被提及的角色 = 本回无戏份，不强行出场
4. **解析归位**：优先按 `【角色名】` 分节格式归位（兼容旧模型输出）；
   若 LLM 不分节（全景叙事流），则回退为「提及归属」把整篇叙述映射到被提到的角色
5. **兜底降级**：输出既无法分节也无法按提及归位时，逐角色独立调用生成，保证每人都能回应

> 骰子判定（`roll(1d100)` 等）同样支持：触发时以系统消息「命运结算」卡片展示。

## 💾 存档机制

- **独立存档**：每个角色各自保存到 `舞台/角色名.child.meph`
- **恢复**：进入舞台时按角色各自恢复存档；「重新开始」则回母版开局
- **删除角色卡**：级联删除该角色的 `.child.meph` 存档
- **只重置进度**：可选「删除存档」仅删除 `.child.meph`，保留母版角色卡

## 📂 内置舞台示例

| 舞台                       | 角色                                               | 场景                                                         |
| -------------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| `Camlann/`（卡美洛之陨）   | `Arthur.meph` × `Mordred.meph`                     | 亚瑟王与莫德雷德的父子终局之战                               |
| `Kurukshetra/`（俱卢之野） | `Arjuna.meph` × `Karna.meph`                       | 摩诃婆罗多战场双雄的对决                                     |
| `Lundao/`（三教论道）      | `Kongzi.meph` × `Laozhi.meph` × `Shijiamouni.meph` | 梦中嵩山论道——孔子、老子、释迦牟尼以「智慧」为辩题，一方胜出 |

## ⚠️ 注意事项

- **角色名唯一**：舞台内各位角色的【角色名】应互不相同（互斥组、记忆注入、气泡着色都按角色名隔离）
- **单卡损坏不拖垮舞台**：某个角色卡解析失败时，该角色被跳过，其余角色正常进入
- **存档不会冒充角色**：`.child.meph` 已被自动过滤，不会在首页显示为额外角色

## 🎭 舞台角色规则设计要点（踩坑实录）

舞台的规则机制与单角色有**本质差异**——每轮生成是「所有角色共享同一段玩家输入、各自独立跑规则引擎」。这个机制对规则设计有两条硬约束，违反它们会得到反直觉的结果（以下问题均在 `Lundao/`（三教论道）舞台开发中实测复现并修复）：

### 1. 不要写「拆招」规则（如 `[克道] if 包含 "道法自然"`）

**错误直觉**：「玩家引了老子的话，我（孔子）应该反驳，所以写一条『玩家提到道法自然时孔子加分』」。

**实际后果**：引擎无法区分「这句话是玩家转述的」还是「玩家帮孔子说的」——任何含「道法自然」的输入，孔子、老子、释迦的拆招规则**全部触发**。实测：

- 玩家输入「无为而无不为」（想帮老子）→ 老子自己 +0（漏触发词），孔子/释迦各 +4
- 玩家输入「仁者爱人」（想帮儒家）→ 老子「克儒」+4 比孔子本家 +3 还多
- 终局三选一被破坏：站队儒家 5 轮后，三方终局条件**同时满足**

**正确做法**：各家只写**本家增益规则**（触发词绑定本家经典），让「玩家站队哪家 → 哪家涨」成为唯一驱动。若想要跨家交锋，用**点名规则**——条件必须带对方角色名（如 `包含 "老子" && 包含 "道"`），且**只加本家维度、不加辩势**（回应他人不构成自己胜利的推进）：

```meph
# 孔子卡：玩家点名老子谈道 → 孔子回应（只加仁德，不推辩势）
[应答老子] if 包含 "老子" && (包含 "道" || 包含 "自然" || 包含 "无为") -> 状态.仁德 += 2
```

### 2. 泛词触发要收窄到「成句/专名」

单字泛词在舞台里会被**所有角色**的规则同时匹配（共享输入）。实测：佛家 `[缘起性空] if 包含 "空"` 会让「仰望天空」「空白」「空间」都触发——`空` 是中文高频字。**本家触发词用成句或本教专名**（如 `缘起` / `般若` / `性空`），把「天空」这类无关输入挡在门外。

### 3. 终局规则必须「一次性」

终局注入规则（条件满足 → 注入结局文本）若无锁，**条件持续满足时每轮都会重新注入同一句结局**。实测 faust 终局后 20 轮持续重复注入。给终局加一次性锁的两种模式：

- **状态锁**：终局触发时置标志位，规则条件加 `状态.归途 == "未决"`（`dantes.meph` 的 `[天平方正]` / `[宽恕彼岸]` 用此模式，双终局互斥）
- **位置/状态迁移锁**：终局动作本身改变条件所依赖的状态（`gilgamesh.meph` 的 `[归来]` 把位置改回「乌鲁克」、`faust.meph` 的 `[灵魂归主]` 把情绪设为「终局」），条件不再满足即天然一次性

### 4. 数值要设软上限 / 下限

共享输入下玩家持续站队一家，无上限累加会导致数值失真（实测：dantes 仇恨涨到 250、joan 士气 325、gilgamesh 哀恸减成负值）。增长规则加 `状态.xxx < 上限`、衰减规则加 `> 下限` 守卫（软上限允许单次增量小幅超限，但禁止无限累加）。

> 💡 这些要点与 [规则书写指南](rule-writing-guide.md) 的「九大反模式」互补：反模式 9 讲单角色下的否定句/语境限定，本节是舞台（多角色共享输入）特有的设计约束。三教论道舞台（`Lundao/`）是这三条要点的完整范例。
