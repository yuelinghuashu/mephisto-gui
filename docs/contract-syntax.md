# 📜 契约语法参考（.meph 文件格式）

> Mephisto 的契约（Contract）是以 `.meph` 为后缀的纯文本文件。
> 它定义了角色的灵魂锚点、世界观、初始状态与行为规则，是叙事引擎的「命运框架」。

## 1. 文件结构

`.meph` 文件由若干**区块（Section）**组成，区块以 `【区块名】` 标题行开头，后续行为区块内容。

```meph
【角色名】
浮士德

【锚点】
- 核心信念：真理比生命更重要

【状态】
- 灵魂完整度：100
- 情绪：永不满足

【世界观】
16 世纪的德意志，一个充满神秘学与契约的世界。

【开局场景】
烛火摇曳的书斋中，浮士德坐在成堆的典籍之间。
```

## 2. 区块总览

| 区块         | 必选 | 说明                                          |
| ------------ | ---- | --------------------------------------------- |
| 【角色名】   | ✅   | 角色名（影响系统提示词中的称谓）              |
| 【锚点】     | 推荐 | 核心人格设定（列表项）                        |
| 【状态】     | 可选 | 初始状态变量（列表项，支持类型推断）          |
| 【世界观】   | 可选 | 世界背景描述（自由文本）                      |
| 【角色背景】 | 可选 | 角色过往经历 / 背景故事（自由文本）           |
| 【开局场景】 | 可选 | 叙事起始场景（自由文本）                      |
| 【历史】     | 可选 | 历史消息快照（`fate` / `assistant` 两种角色） |
| 【记忆】     | 可选 | 长期记忆条目（列表项）                        |
| 【规则】     | 可选 | 行为规则：`[规则名] if 条件 -> 动作`          |

### 约束

- 区块标题独立成行，格式 `【名称】`
- 同一区块**不能重复出现**（重复报错）
- 区块外游离内容报错
- `#` 开头为注释

> **系统保留区块（`@` 前缀）**：以 `@` 开头的区块是系统生成的元数据区块
> （如 `@命运`），与用户书写的 `【】` 叙事区块天然区分。当前仅子版可能含 `@命运`
> 区块——作为「门面区块」置于**文件最顶部**，表示该分支的一句话描述；系统在
> 「另存为分支」时自动写入，首页据此显示「命运一句话」。母版 / 手写文件不必关注。

## 3. 状态值类型

【状态】列表项格式 `- 键：值`，类型自动推断：

| 写法         | 类型   | 示例                   |
| ------------ | ------ | ---------------------- |
| 整数         | int    | `- 灵魂完整度：100`    |
| 浮点数       | double | `- 堕落指数：85.5`     |
| true/false   | bool   | `- 启用：true`         |
| 引号字符串   | string | `- 情绪："暴怒"`       |
| 无引号短文本 | string | `- 位置：书斋`         |
| 空值         | string | `- 备注：`（空字符串） |

> 分隔符支持中文冒号 `：` 与英文冒号 `:`。

## 4. 规则语法

```text
[规则名称] if 条件表达式 -> 动作表达式
```

### 4.1 条件表达式

| 条件       | 示例                              | 含义                           |
| ---------- | --------------------------------- | ------------------------------ |
| 包含文本   | `包含 "黑暗"`                     | 输入包含该文本                 |
| 不包含文本 | `不包含 "真实"`                   | 输入不包含该文本               |
| 状态比较   | `状态.灵魂完整度 < 30`            | 状态变量满足比较               |
| 骰子判定   | `roll(1d100) >= 70`               | 安科风格掷骰（仅 1d2 / 1d100） |
| 逻辑组合   | `(包含 "a" \|\| 包含 "b") && ...` | 括号分组 + `&&` 与 `\|\|` 组合 |

比较符：`==` `!=` `<` `<=` `>` `>=`（两侧不允许空格）。
骰子仅支持两种（其他面数与多骰均报错）：

- `roll(1d2)`：二元判定（是/否、成功/失败）
- `roll(1d100)`：高精度命运判定（1-100）

### 4.2 动作表达式

| 动作     | 示例                          | 含义                 |
| -------- | ----------------------------- | -------------------- |
| 注入叙事 | `注入 "浮士德的灵魂接近枯竭"` | 将文本注入叙事流     |
| 状态赋值 | `状态.位置 = "书斋"`          | 直接设置状态值       |
| 复合赋值 | `状态.堕落指数 += 5`          | 数值增减（+= / -=）  |
| 复合动作 | `注入 "a" && 状态.x += 10`    | 用 `&&` 串联多个动作 |

### 4.3 互斥组

动作前用 `[group:组名]` 标记，组内动作互斥（同轮只执行一条）：

```meph
[答话] if 包含 "船长" -> [group:答话] 注入 "谦逊地笑道"
[缄默] if 包含 "复仇" -> [group:答话] 注入 "沉默不语"
```

### 4.4 执行顺序（两阶段模型）

规则引擎按**两阶段**执行，同一轮中：

1. **阶段一：被动规则批量执行**——动作类型为「状态修改 / 注入叙事」的规则，
   逐条按文件顺序检查；**多条同时命中时全部执行**（互斥组除外，组内只执行第一条命中）
2. **阶段二：主动规则互斥匹配**——动作类型为「LLM 指令 / 静态文本」的规则，
   同样按文件顺序检查，但**只执行第一个命中的规则**（其余即使命中也被跳过）

- 两阶段内部的规则均按文件出现顺序（行号递增）评估
- 互斥组（`[group:组名]`）在各自阶段内按条件命中顺序执行，命中后跳过组内其余动作
- 一个动作属于「被动」还是「主动」，由动作表达式决定：以 `状态.` 修改或 `注入` 开头为被动，
  其余（如 `指令` 等交由 LLM 处理的文本指令）为主动

## 5. 历史与记忆

### 历史（【历史】区块）

```meph
【历史】
- fate: 第一行\n第二行
- assistant：回应
```

- `fate:` 命运（玩家）消息，`assistant:` 叙事响应
- 内容 `\n` 转义为真实换行

### 记忆（【记忆】区块）

```meph
【记忆】
- 浮士德与梅菲斯特签订了契约
- 浮士德正在书斋中
```

## 6. 常见错误

| 场景                        | 提示关键词              |
| --------------------------- | ----------------------- |
| 区块外游离内容              | 无法识别区块            |
| 区块重复                    | 重复的区块              |
| 列表项不以 `-` 开头         | 列表项                  |
| 规则缺少 `->`               | 未找到动作分隔符        |
| 比较符有空格（`> =`）       | 比较运算符              |
| 复合赋值有空格（`+ =`）     | 复合运算符              |
| roll 格式非法 / 括号不匹配  | 骰子表达式 / 括号不匹配 |
| 互斥组缺少 `]`              | 互斥组                  |
| 关键词内部有空格（`包 含`） | 关键词                  |

> 解析器抛出 `MephParseError` 并附带具体原因，编辑器与测试均可即时反馈。
