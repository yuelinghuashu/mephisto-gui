# ⚙️ 规则引擎详解

> 规则引擎是 Mephisto 契约的「行为调度器」：它读取契约中的【规则】区块，
> 在每一轮叙事中检查玩家输入与当前状态，命中条件则执行对应动作，驱动状态的持续演化。

## 1. 规则生命周期

```
玩家输入（命运指引）
    ↓
规则引擎逐条评估【规则】
    ↓
条件命中？ → 执行动作（注入叙事 / 改状态 / 掷骰）
    ↓
状态更新 → 进入下一轮叙事
```

## 2. 规则结构

```
[规则名] if 条件表达式 -> 动作表达式
```

- **规则名**：`[xxx]` 括号内，用于互斥组归属与调试定位
- **条件**：`if` 后的表达式，返回布尔值
- **动作**：`->` 后的表达式，可多个用 `&&` 串联

## 3. 条件系统

### 3.1 包含 / 不包含

匹配玩家输入文本：

```meph
[黑夜] if 包含 "黑暗" -> 注入 "阴影在你身后生长"
[明朗] if 不包含 "黑暗" && 包含 "阳光" -> 注入 "阳光穿透尘埃"
```

### 3.2 状态比较

对契约【状态】中的变量做比较（支持 int / double / string）：

```meph
[濒死] if 状态.灵魂完整度 < 30 -> 注入 "浮士德的灵魂接近枯竭"
[振作] if 状态.灵魂完整度 >= 70 || 状态.情绪 == "满足" -> 注入 "意志重新燃起"
```

> 注意：比较 `==` 用于字符串或数值相等；`!=` 为不等。
> 运算符两侧不允许有空格（`> =` 会报错）。

### 3.3 骰子判定（roll）

安科风格的随机判定，决定事件是否发生或结果倾向：

```meph
[天启] if roll(1d100) >= 80 -> 注入 "命运的齿轮轰然转动"
```

- 仅支持两种骰子（其他面数与多骰均报错）：
  - `roll(1d2)`：二元判定（是/否、成功/失败）
  - `roll(1d100)`：高精度命运判定（1-100）
- 错误写法会报错：`roll(1d6)`（非受支持面数）、`roll (1d100)`（有空格）、`roll(2d100)`（多骰）、`roll(1dx)`（非数字）等

### 3.4 条件组合与优先级

- `&&`（且）优先级高于 `||`（或）
- 括号 `(...)` 可显式分组：

```meph
[抉择] if (包含 "深渊" || 包含 "凝视") && roll(1d100) >= 60 -> 注入 "你听见了深渊的低语"
```

## 4. 动作系统

### 4.1 注入叙事

将文本插入当前叙事流，作为 AI 的输入上下文：

```meph
-> 注入 "契约的一角在阴影中卷起"
```

### 4.2 状态变更

- 简单赋值：`状态.位置 = "书斋"`
- 复合赋值：`状态.堕落指数 += 10` / `状态.灵魂完整度 -= 5`（数值类型才允许）

### 4.3 复合动作

用 `&&` 串联多个动作，按顺序执行：

```meph
[契约] if 包含 "契约" && roll(1d100) -> 注入 "契约生效" && 状态.灵魂完整度 += 10
```

## 5. 互斥组

同组规则的动作**互斥**——同轮只要命中并执行了一条，其余跳过：

```meph
[答话] if 包含 "船长" -> [group:船长回应] 注入 "谦逊地笑道"
[缄默] if 包含 "复仇" -> [group:船长回应] 注入 "沉默不语"
```

- 组名随意，但同组规则必须使用相同 `[group:组名]`
- 组内按文件顺序评估，先命中者执行

## 6. 实际示例（内置 faust.meph）

```meph
【规则】
[灵魂危机] if 状态.灵魂完整度 < 30 -> 注入 "浮士德的灵魂接近枯竭"
[契约觉醒] if 包含 "契约" && roll(1d100) -> 状态.灵魂完整度 += 10
```

- 「灵魂危机」：当灵魂完整度低于 30 时，注入一段警示叙事
- 「契约觉醒」：玩家提到「契约」且有概率（掷骰）成功时，灵魂完整度 +10
