# 🧠 记忆系统

> 记忆系统让 AI 叙事**跨越单次对话**保持一致性：它自动提取关键事件、去重、压缩，
> 并以「记忆」形式注入系统提示词，塑造角色的长期连续性。
>
> **极简核心**：记忆永久保存在 `.meph` 存档中永不删除；每轮注入时按重要性
> 权重排序、超出预算则裁剪（放不下的仍在文件里，不是遗忘），从根本上保障
> 「角色不崩人设」。

## 1. 记忆的生命周期

```text
对话进行中（命运 ↔ 角色）
    ↓
每 3 轮触发记忆提取（maybeExtract）
    ↓
从最近 20 条消息提取 2-5 条核心事件摘要
    ↓
去重（与现有记忆比对，跳过重复）
    ↓
超过 30 条？ → 压缩（旧记忆摘要 + 保留最近 5 条；高权重永不压缩）
    ↓
记忆列表按重要性降序、受上限裁剪后注入系统提示词
```

## 2. 提取时机

- 每 **3** 轮对话提取一次（由 `extractInterval = 3` 控制）
- 轮数按「命运（玩家）」消息计数
- 提取窗口为最近的 **20** 条消息（`extractWindow = 10` × 2，含命运与角色消息）

## 3. 提取规则

MemoryManager 通过 LLM 提示词约束提取行为：

1. 提取 **2-5 条**对角色有重大影响的核心事件，覆盖整段剧情推进
2. 回顾整段对话的事件链，而非只取最后一句话
3. 每条摘要 20-60 个字，保留关键人物、地点、动作与信息
4. 忽略日常寒暄与无意义对话
5. 与现有记忆重复的不再提取
6. **禁止修改/重复角色的核心设定**（角色名、锚点、状态值等）
7. 输出格式：每行一条，以 `- [权重] 内容` 开头
   - 权重为 1-5 的整数，表示这条记忆对角色塑造的重要性：
     5 = 角色核心誓言 / 4 = 重大剧情事件 / 3 = 一般进展 / 2 = 次要信息 / 1 = 边缘细节
   - 无法判断权重时使用默认 3

> **自动权重分配**：提取时 LLM 会为每条新记忆分配 1-5 权重，
> 使自动积累的「重大事件」也能获得高权重进入「永不压缩 + 优先注入」保护。
> 无法判断权重时兜底默认 3。

## 4. 去重与压缩

### 去重

- 新提取的记忆与现有记忆逐条比对（按内容去重）
- 完全重复的条目被丢弃
- **权重升级**：内容相同但新权重更高时，旧记忆权重自动升级
  （新权重 ≤ 旧权重才丢弃）——LLM 后续识别出同一事件更重要时不会丢失升级

### 压缩（超限触发）

- 记忆总数上限 **30 条**（`maxLimit`）
- 超过上限时触发压缩：
  - 旧记忆（除最近 5 条外）交给 LLM 压缩成不超过 5 条摘要
  - **保留最近 5 条**（`compressRetain`）原文
  - **高权重记忆（importance ≥ 4）默认永不参与压缩**——人设核心无论如何不会丢失
  - 高权重记忆超过 **15 条**（`highImportanceCap`）时，最低权重的高权重记忆降级参与压缩，
    防止高权重无限膨胀导致 token 消耗失控
  - 压缩后的摘要 + 最近原文 + 高权重原文合并为新的记忆列表

## 5. 记忆如何影响叙事

- 记忆列表作为系统提示词的一部分注入，为 LLM 提供「这个角色经历了什么」的长期上下文
- **按重要性权重降序注入**：高权重（人设核心/重大事件）在前，让模型优先关注
- **可设注入条数上限（`maxMemories`）**：超限时高权重记忆全部保留 + 其余按权重
  降序补足上限——窗口放不下的记忆**仍在存档中**，只是本轮不带，并非遗忘
- **设置页「记忆注入上限」**：用户可在设置页选择 10 / 20 / 30 / 全部注入
  四档（默认 20 条），控制每轮发送给 LLM 的记忆条数上限，偏好持久化
- 配合契约的【记忆】区块（初始记忆）与运行时动态提取的记忆，共同构建角色一致性

## 6. 记忆重要性（创作者手动标记）

`.meph` 的【记忆】区块中，每条记忆可用 **`[权重]` 前缀**手动标记重要性（1-5 星）：

```text
【记忆】
- [5] 我是浮士德，与梅菲斯特立下赌约
- [4] 曾因知识之渴将灵魂抵押给魔鬼
- 常规旅途见闻（无前缀 = 默认 3 星）
```

| 权重        | 含义                | 行为                                 |
| ----------- | ------------------- | ------------------------------------ |
| `[5]`       | 人设核心 / 不可动摇 | 永不压缩；注入时优先第一梯队         |
| `[4]`       | 重大事件 / 关键关系 | 永不压缩；注入时优先第二梯队         |
| 无 / `[3]`  | 普通事件            | 可被压缩；注入时靠后                 |
| `[2]` `[1]` | 次要细节            | 可被压缩；注入时最靠后（可能被裁剪） |

**手动标记的意义**：

- 创作者可在 `.meph` 中直接锁定「这条记忆对角色很重要」，系统自动给予
  「优先注入 + 永不压缩」双重保护
- 无前缀的旧格式记忆自动按 3 星处理，**完全向后兼容**

## 7. 失败降级策略

| 场景             | 行为                                  |
| ---------------- | ------------------------------------- |
| LLM 调用失败     | 静默跳过本次提取/压缩，保留原记忆列表 |
| 提取结果为空     | 返回原记忆列表                        |
| 提取结果全部重复 | 返回原记忆列表                        |
| 压缩结果为空     | 保留原记忆列表                        |

> 记忆系统**永远不会**因 LLM 异常而中断叙事主流程。

## 8. 相关代码与常量

| 项                        | 值   | 说明                                                  |
| ------------------------- | ---- | ----------------------------------------------------- |
| `extractInterval`         | 3    | 每 N 轮提取一次                                       |
| `extractWindow`           | 10   | 提取窗口（× 2 = 20 条）                               |
| `maxLimit`                | 30   | 记忆总数上限                                          |
| `compressRetain`          | 5    | 压缩时保留的最近条数                                  |
| `highImportanceThreshold` | 4    | 高权重阈值（≥4 默认永压缩保护）                       |
| `highImportanceCap`       | 15   | 高权重记忆最多保留条数（超过后最低权重降级参与压缩）  |
| `maxMemories`             | null | 注入条数上限（null=全注入；设置页可选 10/20/30/全部） |

核心实现：`lib/services/memory/memory_manager.dart`
