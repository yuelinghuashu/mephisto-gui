# 📖 规则书写指南：高效契约的实践方法论

> [规则引擎详解](rule-engine.md) 回答「语法怎么写才**合法**」；本篇回答「**怎么写才高效、正确、可持续**」。
> 以下反模式均来自内置契约的真实修复案例——它们不是理论推导，而是曾被玩家真实踩中的坑。

## 1. 书写前自问：八项设计检查清单

写一条规则前，先回答这八个问题：

| #   | 问题                                                                                               | 若不回答会怎样                             |
| --- | -------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1   | **这条规则会在什么场景触发？** 脱离玩家的「当前位置 / 当前状态」是否有意义？                       | 跨场景误触发（见反模式 1）                 |
| 2   | **条件是否用了「否定黑名单」来推断语义？**                                                         | 无法穷尽所有情形（见反模式 2）             |
| 3   | **规则依赖的状态值，能否从初始状态到达？** 有没有规则为其提供来源？                                | 状态链断裂，规则永不触发（见反模式 3）     |
| 4   | **这是被动规则吗？条件是否只含数值阈值？**                                                         | 每轮自动触发的惩罚循环（见反模式 4）       |
| 5   | **终局类规则的达成条件会不会过苛？** 多个硬性关键词叠加是否让玩家几乎不可能触发？                  | 终局永远无法达成（见反模式 5）             |
| 6   | **互斥组里有没有对偶规则？** 只有一条规则的组是否还有「互斥」意义？                                | 互斥语义形同虚设（见反模式 6）             |
| 7   | **这条规则输出的文案，是应该每次一样，还是应随叙事流变化？** 若应随剧情变化，是否该交给 LLM 即兴？ | 叙事重复、角色像复读机（见反模式 7）       |
| 8   | **LLM 指令的触发条件是否过宽？** 是否只用角色名 / 高频泛词就触发主动输出？                         | 高频误触发、挤占其他主动叙事（见反模式 8） |

---

## 2. 八大反模式与正确写法

### 反模式 1：规则不绑定场景状态 → 跨场景误触发

**错误写法**（`joan_of_arc.meph` 修复前）：开局在希农城堡（宫廷），战场规则却无位置约束——玩家在宫廷里说「冲锋」「受伤」也会触发战场规则：

```meph
[负伤] if 包含 "受伤" || 包含 "中箭" || 包含 "流血" -> 状态.生命 -= 10
```

**问题**：宫廷里没有战事，「受伤 / 中箭」是战场语境。规则没有绑定位置，导致宫廷场景凭空扣血。

**正确写法**：给战场规则加 `状态.位置 != "希农"` 约束，并新增场景转换规则打通「宫廷 → 战场」：

```meph
[出征] if 状态.位置 == "希农" && (包含 "出征" || 包含 "出发") -> 状态.位置 = "奥尔良"
[负伤] if 状态.位置 != "希农" && (包含 "受伤" || 包含 "中箭") -> 状态.生命 -= 10
```

> 💡 **位置是叙事场景的「坐标」**。凡是描述「在某个地方发生的事」的规则，都应该考虑是否要绑定位置。

---

### 反模式 2：用「不包含黑名单」推断语义 → 无法穷尽

**错误写法**（`arthur_sword.meph` 修复前）：用排除敌军来推断「这是需要悔的冲动」：

```meph
[王的怒火] if 包含 "愤怒" && 不包含 "敌人" && 不包含 "撒克逊" && ... -> 状态.悔意 += 10
```

**问题**：隐含了「对非敌军发怒 = 错」的错误假设。亚瑟对**盗贼、恶霸、暴吏**发怒并出手是正当的，不该悔。黑名单永远列不完所有「该怒而不该悔」的目标。

**正确写法**：用**正向语义**捕捉「悔意」的真正触发条件——玩家明确表达伤害了不该伤害的人（无辜者 / 弱者）：

```meph
[王的怒火] if (包含 "愤怒" || 包含 "冲动") && (包含 "无辜" || 包含 "平民" || 包含 "弱者" || 包含 "过当") -> 状态.悔意 += 10
```

| 玩家输入               | 触发悔意 | 合理性              |
| ---------------------- | -------- | ------------------- |
| 「我对无辜平民动了怒」 | ✅       | 伤害弱者 → 该悔     |
| 「我要教训那个盗贼」   | ❌       | 惩罚恶人正当 → 不悔 |

> 💡 **能用正向关键词描述语义时，绝不用「不包含」做否定推断**。「不包含」只能用于「这几种明确情况不发生」，不能用于「语义是……的补集」。

---

### 反模式 3：状态链断裂 → 规则永远不触发（有消费无来源）

**错误写法**（`arthur_sword.meph` 修复前）：状态 `悔意` 初始 0，且没有任何规则能为它增加值，却有规则要求 `悔意 >= 20`：

```meph
【状态】
- 悔意： 0

【规则】
[忏悔] if 状态.悔意 >= 20 && ... -> 状态.悔意 = 0
```

**问题**：`悔意` 永远是 0，`[忏悔]` 的 `>= 20` 永远不可能为真——整个「愤怒 → 积怨 → 自省 → 释怀」闭环失效，且创作者很难发现（规则语法合法、解析不报错）。

**正确写法**：先补上悔意的来源规则，再让消费规则依赖它：

```meph
[王的怒火] if ... -> 状态.悔意 += 10
[忏悔] if 状态.悔意 >= 20 && (包含 "自责" || 包含 "忏悔") -> 状态.悔意 = 0 && 状态.信心 -= 5
```

> 💡 **检查状态链**：对每一个「消费」状态的规则，反推是否存在「生产」该状态的规则或初始值。断裂的链条是静默的——解析器不会报错，但规则永不触发。

---

### 反模式 4：纯阈值被动规则 → 每轮自动触发，形成惩罚循环

**错误写法**（`Camlann/Arthur.meph` 修复过程中的失误）：把条件从「阈值 + 关键词」改成纯阈值：

```meph
[旧伤] if 状态.伤疤 >= 10 -> 状态.王权威严 -= 5
```

**问题**：被动规则（`状态.` 修改）**每轮都会求值**。只要 `伤疤 >= 10`，无论玩家这轮说什么，都会自动扣减王权威严——且没有规则能消除伤疤，扣减将无限持续直到数值打穿。

**正确写法**：保留 `包含` 关键词作为**主动门控**，让玩家在「提及旧伤」时才触发，避免每轮自动惩罚：

```meph
[旧伤] if 状态.伤疤 >= 10 && 包含 "旧伤" -> 状态.王权威严 -= 5
```

> 💡 **被动规则 + 纯数值阈值 = 自动兵工厂**。凡是被动规则（动作以 `状态.` 或 `注入` 开头），条件里尽量保留至少一个 `包含` / `不包含` 关键词或骰子，让触发依赖于「玩家的行为」，而不是「数值一到就自动触发且无限循环」。

### 反模式 5：终局条件叠加过多硬约束 → 几乎无法达成

**错误写法**（浮士德契约修复前）：终局要求玩家**同时**说出「停留」和「够了」两个词，且灵魂完整度达标：

```meph
[说出停留] if 包含 "停留" && 状态.灵魂完整度 >= 80 && 包含 "够了" -> ...
```

**问题**：「够了」是玩家在自然对话中极少使用的词。多重硬性关键词叠加，让终局在实战中几乎不可能触发，玩家永远无法抵达原典结局。

**正确写法**：终局只保留**一个**语义关键词 + 状态门槛：

```meph
[说出停留] if 包含 "停留" && 状态.灵魂完整度 >= 80 -> ...
```

> 💡 **终局规则的硬约束越少越好**。数值达标的累积过程本身就是「前置难度」，关键词只负责「识别玩家的意图动作」。

---

### 反模式 6：单边互斥组 → 互斥语义形同虚设

**错误写法**（`faust` / `gilgamesh` 修复前）：互斥组内只有一条规则：

```meph
[暗影缠身] if ... -> [group:侵蚀] 状态.灵魂完整度 -= 5
[抗争] if ... -> [group:命运] 状态.求索 += 10
```

**问题**：互斥的意义是「**命中 A 就不执行 B**」。组内只有一条规则时，没有对偶可互斥——组标签成了摆设。

**正确写法**：为每组补上语义对偶规则：

```meph
# faust：黑暗侵蚀 ↔ 光明回暖
[暗影缠身] if 包含 "黑暗" -> [group:侵蚀] 状态.灵魂完整度 -= 5
[烛火映心] if 包含 "光明" -> [group:侵蚀] 状态.灵魂完整度 += 5

# gilgamesh：抗争命运 ↔ 臣服命运
[抗争] if 包含 "挑战" && 包含 "命运" -> [group:命运] 状态.求索 += 10
[臣服] if 包含 "认命" || 包含 "放弃" -> [group:命运] 状态.求索 -= 20
```

> 💡 **互斥组 = 一段「行为抉择」**。每条互斥组都应该对应一个明确的二选一（或 N 选一）叙事节点：战或降、怒或悔、抗争或臣服。

### 反模式 7：LLM 指令动作写死文案 → 叙事重复失忆

**错误写法**：用 `注入` 把角色的对白/反应写成固定台词：

```meph
[梅菲斯特低语] if 包含 "低语" -> 注入 "梅菲斯特冷笑着靠近，低声说：『与我作一场交易如何？』"
```

**问题**：每次触发都是同一句话，无视已经展开的叙事流——玩家第三次听到时角色像复读机，且台词可能与前面已发生的剧情脱节（失忆感）。角色对白属于**创造性输出**，应随情境、前文与角色当下状态而变化。

**正确写法**（`Kurukshetra/Arjuna.meph` 的范例）：用**主动规则（LLM 指令）**描述「谁在说话、意图是什么、风格/底线如何」，具体言辞由 LLM 结合当前叙事流即兴生成：

```meph
[黑天低语] if 包含 "黑天" || 包含 "奎师那" -> 黑天开口，以神的视角敦促{角色名}记起自己为何而战——但不可以简单说服他，要让他自己认清法与不忍的界限
```

注意这里的动作**不是** `注入 "..."` 或 `状态.xxx` 开头——它是主动规则的指令描述，会被作为指令注入 LLM 输入。

**💡 判断标准**：

| 文案性质                                                                   | 该用                 |
| -------------------------------------------------------------------------- | -------------------- |
| 这句内容在每次叙事里**应该永远一样**（契约条款、关键台词、必须锚定的事实） | `注入`               |
| 这句内容应**随情境 / 前文 / 角色状态变化**（角色对白、动作反应的文学描写） | LLM 指令（主动规则） |

---

### 反模式 8：LLM 指令触发条件过宽 → 高频误触发

**错误写法**（`faust.imperial.meph` / `Kurukshetra` 修复前）：用**单个角色名**或**高频泛词**作为 LLM 指令的触发条件：

```meph
[梅菲斯特耳语] if 包含 "梅菲斯特" || 包含 "弄臣" -> 梅菲斯特以弄臣的谄媚口吻靠近{角色名}，用权力、金钱与美人的言辞诱惑他沉溺于这场宫廷大戏
```

**问题**：梅菲斯特是宫廷大戏的核心角色、无时无刻不在场——玩家质问他、试探他、甚至随口提到他，都会被同一句「谄媚靠近、出言诱惑」强制打断。更糟的是，主动规则（LLM 指令）是**互斥匹配**的，同轮只执行第一条命中；高频规则会挤占其他主动叙事空间，让剧本反复回到同一个动作。`Kurukshetra/Karna.meph` 的 `[敬敌]`（`包含 "阿周那"`——对面主将名，讨论战术就触发）与 `[黄金甲]`（`包含 "铠甲"`——战场高频泛词，谈敌军铠甲也触发）是同类问题：与语境脱节的固定情感输出反复出现。

**正确写法**：给 LLM 指令条件加上**语境词门控**——只有玩家明确表达对应意图时才触发：

```meph
# 角色名 / 物品名 + 语境词共同门控
[梅菲斯特耳语] if (包含 "梅菲斯特" || 包含 "弄臣") && (包含 "低语" || 包含 "耳语" || 包含 "引诱" || 包含 "蛊惑") -> 梅菲斯特以弄臣的谄媚姿态靠近{角色名}，用权力、金钱与美人的言辞诱惑他
[敬敌] if 包含 "阿周那" && (包含 "敬" || 包含 "憾" || 包含 "兄弟" || 包含 "可惜") -> {角色名}流露出对阿周那的复杂敬意
[黄金甲] if 包含 "黄金甲" -> {角色名}提及已献给因陀罗的黄金甲，但笃定太阳的庇护从未离开
```

> 💡 **LLM 指令的触发条件应与玩家意图对齐**。角色名 / 高频词只负责「角色在场感」，不该单独挑起 LLM 主动输出；主动输出应由「角色名 / 特殊物品名 + 明确的互动语境词」共同门控。若只需角色在场的存在感，用被动 `注入` 描写即可，不必动用 LLM 指令。

## 3. 场景链模式：用位置状态机组织多阶段叙事

规则绑定位置（见反模式 1）的进阶用法，是**用位置作为「场景链」的游标**，组织一段从「出发 → 旅途 → 抵达 → 归来」的完整弧线。

以 `gilgamesh.meph` 的三幕结构为例：

```text
乌鲁克(开场) ──[启程]──▶ 荒野 ──[抵尽头]──▶ 世界尽头 ──[归来]──▶ 乌鲁克(终点)
```

```meph
# 场景转换（改变位置 = 推进场景）
[启程] if 状态.位置 == "乌鲁克" && (包含 "出发" || 包含 "启程") -> 状态.位置 = "荒野" && 状态.求索 += 10
[抵尽头] if 状态.位置 == "荒野" && (包含 "尽头" || 包含 "海边") -> 状态.位置 = "世界尽头" && 状态.求索 += 15

# 旅途遭遇（只在「离开乌鲁克」后触发）
[狮战] if 状态.位置 != "乌鲁克" && (包含 "狮子" || 包含 "猛兽") -> 状态.王权 += 5

# 终局（必须在世界尽头且求索达标）
[归来] if 状态.位置 == "世界尽头" && 状态.求索 >= 100 && (包含 "回家" || 包含 "归来") -> 状态.位置 = "乌鲁克" && 状态.王权 += 15
```

**设计要点**：

1. **位置只允许被场景转换规则改变**——不要让普通规则随意改位置，否则场景链会乱序
2. **每个场景阶段的规则，用 `位置 == 当前场景` 或 `位置 != 初始场景` 约束**——把规则"锁"在它所属的章节
3. **终局规则绑定「终点位置 + 达标数值」**——既确保玩家走完旅程，又允许玩家用关键词主动收尾

## 4. 规则与 LLM 的分工边界

规则引擎是**确定性**的，LLM 是**创造性**的。书写高效契约的关键，是明确两者的边界——**该确定的事用规则保证，该创造的事交给 LLM 发挥**。

| 事务类型                                              | 该用规则还是 LLM                | 理由                                             |
| ----------------------------------------------------- | ------------------------------- | ------------------------------------------------ |
| 状态数值变化（生命 / 信仰 / 士气增减）                | **规则**                        | 必须精确、可被玩家察觉、形成反馈闭环             |
| 骰子判定（成败 / 概率事件）                           | **规则**                        | 引擎提供 `roll(1d100)` 结构化结果与命运结算卡片  |
| 叙事转折的**触发条件**（何时进入终局 / 何时转变心态） | **规则**                        | 需要确定性，避免「命运」被 LLM 随意决定          |
| 角色的对话、动作描写、情感表达                        | **LLM**                         | 需要创造性与文学性，规则无法穷举                 |
| 玩家语境的**语义理解**（「惩罚盗贼」vs「伤害无辜」）  | **LLM 为主 + 规则捕捉明确信号** | LLM 理解语境；规则只捕捉玩家明确表达的语义关键词 |

**反模式 2 的修复正是这一边界的体现**：何时该悔、何时不该悔，本质是语义理解——交给 LLM 叙事；规则只负责捕捉玩家明确说出的「无辜 / 弱者 / 平民」这些不可辩驳的悔意信号。**规则不该替 LLM 做推断，只该确认明确的事实。**

**反模式 7 则是这条边界在「动作输出」维度的体现**：状态数值和触发条件用规则保证确定性，而角色对白与文学描写属于创造——用 LLM 指令描述意图，把具体言辞的生成权交还给 LLM。
